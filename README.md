# Slurp PC Boost

Демонстрационное WPF-приложение (.NET 8) — оптимизатор ПК для геймеров в стиле **hone.gg**:
тёмный интерфейс, живой график FPS, твики Windows по категориям, игровые профили и журнал действий.

> ⚠️ **Важно: это ДЕМО.** Приложение ничего не меняет в системе — ни реестр, ни службы,
> ни схемы питания, ни сетевые настройки. Все «оптимизации» имитируются (задержка + запись в журнал),
> чтобы можно было безопасно показать интерфейс и логику. Как превратить демо в рабочий твикер —
> см. раздел «Как сделать оптимизатор настоящим».
>
> Проект учебный и не связан с hone.gg / AuraSide, Inc.

## Что внутри

| Раздел | Возможности |
|---|---|
| **Обзор системы** | Круговой индикатор оптимизации, текущий FPS/1% low/пик, загрузка CPU/GPU/RAM, живой график кадров (30 с), плитки с реальной информацией о железе, кнопки «Сканировать / Оптимизировать / Откатить», игровой режим, авто-оптимизация, пауза мониторинга |
| **Оптимизация** | 20 твиков в 6 категориях (Процессор, Память, Видеокарта, Сеть, Windows, Игровой режим), фильтр по категориям, свитчи с состояниями «Выключено / Применяется… / Применено», пометка «Продвинутое» с подтверждением, массовые операции с прогрессом |
| **Игры** | 12 игровых профилей с поиском и фильтрами по жанру, включение/отключение профиля, «пресет» (Киберспорт / Максимальный FPS) |
| **Журнал** | Цветные записи по уровням (успех/предупреждение/ошибка), сохранение журнала в файл, открытие папки с логами, автопрокрутка |
| **Настройки** | Профиль оптимизации, авто-оптимизация, пауза мониторинга, игровой режим, сброс статистики, откат всех твиков, информация об устройстве и статистика сессии |

Всё это **без единой сторонней NuGet-зависимости** — только `Microsoft.NET.Sdk`, WPF и стандартная библиотека.

## Требования

- **Windows 10/11**
- **.NET 8 SDK** (или Visual Studio 2022 17.8+ с рабочей нагрузкой «.NET desktop development» / «Разработка классических приложений .NET»)

Проект собирается и под Linux/macOS (`EnableWindowsTargeting=true`) — удобно для CI, но запускать только на Windows.

## Сборка и запуск

```bash
# из корня репозитория
dotnet build src/SlurpPcBoost/SlurpPcBoost.csproj -c Debug
dotnet run   --project src/SlurpPcBoost/SlurpPcBoost.csproj
```

В Visual Studio: откройте `src/SlurpPcBoost/SlurpPcBoost.csproj` и нажмите **F5**.

### Публикация одним self-contained .exe (без установки .NET у пользователя)

```bash
dotnet publish src/SlurpPcBoost/SlurpPcBoost.csproj -c Release -r win-x64
```

Готовый файл: `src/SlurpPcBoost/bin/Release/net8.0-windows/win-x64/publish/SlurpPcBoost.exe`
(в Release уже включены `SelfContained`, `PublishSingleFile`, сжатие и встроенная отладочная информация —
это задано в `SlurpPcBoost.csproj`).

Для ARM64-устройств: `-r win-arm64`.

## Структура проекта

```
src/SlurpPcBoost/
├─ App.xaml / App.xaml.cs           # точка входа: сервисы → состояние → главное окно
├─ MainWindow.xaml(.cs)             # кастомная шапка (WindowChrome), сайдбар, страницы, статус-бар, оверлей работы
├─ app.manifest                     # DPI PerMonitorV2, уровень прав asInvoker (демо ничего не требует)
├─ Assets/app.ico                   # иконка exe (в окне иконка рисуется кодом)
├─ Mvvm/                            # ObservableObject, RelayCommand, AsyncRelayCommand
├─ Converters/                      # BoolToVisibility, BoolNegation, EmptyStringToVisibility, RingDash, FilterEquals
├─ Models/                          # Tweak, TweakGroup, TweakCatalog, GameProfile, LogEntry, InfoItem, CategoryInfo
├─ Services/
│   ├─ CatalogService.cs            # каталог твиков и игровых профилей
│   ├─ OptimizationEngine.cs        # ⭐ сюда подключается реальная оптимизация (сейчас — имитация)
│   ├─ AppState.cs                  # центральное состояние: твики, настройки, метрики, таймер 500 мс
│   ├─ FpsMonitor.cs                # «FPS» (демо-сигнал; в реальном приложении — ETW PresentMon)
│   ├─ SystemInfoService.cs         # CPU/GPU/RAM/ОС из реестра и kernel32, без WMI и лишних пакетов
│   ├─ AppLogService.cs             # журнал в UI + сохранение в %AppData%\SlurpPCBoost\logs
│   └─ DialogService.cs             # подтверждения и информационные окна
├─ ViewModels/                      # Main, Dashboard, Optimize, Games, Settings, Log
├─ Views/                           # DashboardView, OptimizeView, GamesView, SettingsView, LogView
└─ Themes/                          # Colors.xaml (палитра), Icons.xaml (33 векторные иконки), Styles.xaml (тёмная тема)
```

### Архитектура

- **MVVM без сторонних библиотек**: `INotifyPropertyChanged` + `ICommand` (свой `AsyncRelayCommand` с защитой от повторного запуска).
- **Одно состояние на всё приложение** (`AppState`): страницы подписаны на его свойства через обычные привязки,
  вью-модели содержат только команды и логику конкретной страницы.
- **Таймер 500 мс** обновляет FPS-монитор, нагрузку и перестраивает `PointCollection` для графика.
- **Все данные о железе — настоящие** (реестр, `GlobalMemoryStatusEx`, `Environment`), чтобы интерфейс не выглядел «пустым».
- **Демо-математика**: оценка производительности `Score01 = 0.15 … 1.0` (доля веса применённых твиков),
  FPS пересчитывается как `30 + Score01 * 270`, максимум прироста — `+38 %`.

## Как сделать оптимизатор настоящим

1. **Права администратора.** В `app.manifest` замените `level="asInvoker"` на `level="requireAdministrator"`.
2. **Реальные действия.** В `Services/OptimizationEngine.cs` методы `ApplyAsync` / `RevertAsync` сейчас только ждут
   и пишут в журнал. Подключите туда свои операции, например:
   - план питания: `powercfg /setactive SCHEME_MIN`;
   - отключение служб: `sc stop SysMain`, `sc config ... start=disabled` (или через `ServiceController`);
   - реестр: `Microsoft.Win32.Registry.LocalMachine.SetValue(...)` (`Tweak.Id` удобно использовать как ключ настройки);
   - сеть: `ipconfig /flushdns`, `netsh int tcp set global ...`.
3. **Обязательные правила безопасности** (иначе получится «оптимизатор», ломающий Windows):
   - перед изменением — **бэкап** исходного значения (реестр: экспорт ветки; службы: исходный `StartType`);
   - каждый твик обязан иметь **рабочий откат** (кнопка «Откатить всё» уже есть в UI);
   - сначала реализуйте безопасные твики (`TweakRisk.Safe`), «продвинутые» оставляйте под явное подтверждение;
   - для расчёта «до/после» замените демо-модель FPS на реальный захват кадров (ETW: PresentMon) и счетчики производительности.

## Возможные вопросы

**Не собирается, ошибка про `net8.0-windows` / Windows Desktop.**
Установите .NET 8 SDK; в Visual Studio — рабочую нагрузку «Разработка классических приложений .NET».

**Хочу обычное окно, а не кастомную шапку.**
В `MainWindow.xaml` уберите `WindowStyle="None"` и блок `shell:WindowChrome.WindowChrome` — вся вёрстка останется рабочей.

**Как убрать иконку из exe.**
Закомментируйте `<ApplicationIcon>Assets\app.ico</ApplicationIcon>` в `SlurpPcBoost.csproj`.

**Почему «FPS» не настоящий?** Демо-режим: без инжекта в игру или ETW-трейсинга реальный FPS не получить.
График — правдоподобная симуляция, которая реагирует на применённые твики.
